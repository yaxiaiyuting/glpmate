# GLP Mate

一个**自托管**的 GLP-1 用药记录与药代动力学估算工具。数据全部存在你自己的设备上，不经过任何第三方服务器。

针对**替尔泊肽（tirzepatide）**和**司美格鲁肽（semaglutide）**等 GLP-1 受体激动剂，提供：

- **用药记录与体内水平估算** —— 基于说明书参数的群体药代动力学模型（一室模型 + 一阶吸收），画出体内药物水平的估算曲线
- **每日记录** —— 体重、体脂、腰围、血压、血糖、饮食、饮水、训练、睡眠、副作用
- **营养与饮水目标** —— 按天统计并对照目标
- **趋势图表** —— 可触摸读数，按时间范围切换
- **可选 AI 教练** —— 用你自己的 API key，读取你的真实记录做整理与解读

## ⚠️ 这不是医疗器械

**本项目提供的体内药物水平是估算，不是血药浓度测量。**

它用说明书公开的群体药代动力学参数（半衰期、达峰时间、生物利用度）做数学建模，输出的是"按平均人群推算的典型值"。**个体差异可能很大**——年龄、体重、肾功能、注射部位、抗体都会影响真实血药浓度。

**请勿用它做以下决定**：调整剂量、停药、判断是否漏打、判断是否过量。这些请咨询你的医生。

界面上所有估算数字都带有"估算（非血药浓度）"标注，这是刻意的设计，请不要为了"看起来更干净"而移除。

## 数据来源

所有药代参数与疗效数字都来自公开的说明书与已发表论文，并在代码里保留了**逐条引用**（`claim` / `url` / `quote`）：

- FDA 说明书 ZEPBOUND (tirzepatide) NDA 217806 §12.3 —— 半衰期约 5 天、tmax 中位 24 小时（范围 8–72）、生物利用度 80%、4 周达稳态
- SURMOUNT-1 / SURMOUNT-2 等 III 期试验 —— 减重幅度与胃肠道不良反应发生率
- 中国成人 BMI 标准 WS/T 428-2013 —— 超重 ≥24、肥胖 ≥28（**不是** WHO 的 25/30）

核验过的数据在 `research/` 目录下，包含原文引用。完整的出处清单、软件依赖许可、
以及本项目的边界说明见 [ACKNOWLEDGMENTS.md](ACKNOWLEDGMENTS.md)。

## 体内水平是怎么算的

一室模型 + 一阶吸收（Bateman 方程），两个参数直接来自说明书：半衰期 120 h、tmax 中位 24 h。tmax 用来反解吸收速率常数 ka：

```
ka/(ka−ke) · (e^(−ke·t) − e^(−ka·t))        ke = ln2 / 半衰期
```

几点容易出错、本项目特意钉住的地方：

**① 峰值不是注射瞬间。** 打完针 t=0 时体内是 0，24 小时后才达峰。要看到"上升 → 达峰 → 回落"。

**② 达峰时体内 ≈ 剂量的 87%，不是 100%。** 因为达峰之前已经有一部分被清除了。如果模型说"2.5 mg 的针打进去、体内峰值 2.5 mg"，那是错的——**体内不可能比打进去的总量还多**。这条有专门的回归测试（`TestDoseMassConservation`）。

**③ 首剂只到稳态的约 61%。** 稳态要 4 周才建立，所以第一针的水平看着"低"是正常的。

**④ 未来剂量会计入曲线。** 末尾那段陡升是下一针的预测，不是已经发生的事。

**⑤ 这是估算，不是血药浓度。** 个体差异可能很大，请勿据此调整剂量。


## 运行（后端 + Web 界面）

只需要 Python 3.10+：

```bash
python3 run.py
```

**核心功能零第三方依赖**（记录、图表、药代计算、提醒全部只用标准库）。
唯一可选的是 **Pillow**：装了它，AI 教练的拍照识餐会把图片压到 1024px 再上传
（省流量、省 token）；没装也能用，图片按原样上传。代码里是懒加载并捕获
`ImportError`，所以装不装都不会影响启动。

```bash
pip install Pillow        # 可选，仅影响拍照识餐的上传体积
```

然后浏览器打开 `http://127.0.0.1:8848`。数据默认存在 `data/glpmate.db`。

常用参数：

```bash
python3 run.py --db /path/to/my.db        # 指定数据库
python3 run.py --port 9000                # 换端口
python3 run.py --import-hitrack <目录>    # 导入华为运动健康轨迹
```

## 构建 Android 客户端

需要 JDK 21（**JDK 25+ 会导致 Gradle 失败**）和 Android SDK：

```bash
cd android
python3 tools/sync_backend.py     # 把 glpmate/ 同步进 APK 资源（改动后端后必须跑）
python3 tools/gen_stamp.py        # 更新解压戳记（同步脚本会顺带提醒）
./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/app-debug.apk`。APK 内嵌 CPython（Chaquopy），**装完即用，不需要 Termux 或任何外部程序**。

> **同步脚本是必需的，不是可选的。** APK 里的 Python 代码是 `glpmate/` 的副本；改了后端不同步，设备上就会一直跑旧代码。`gen_stamp.py` 用源码内容哈希做解压戳记，避免"装了新 APK 但跑的还是旧代码"这种没有任何报错的故障（这个坑我们踩过两次）。

## 设计上的一些取舍

**为什么没有缩放和平移？** 图表最初做过双指缩放 + 单指平移，结果是三个 bug（值域随窗口崩、边界处 `coerceIn` 抛异常、手势互相抢事件）。现在整条序列一屏画完、只用游标读数——这是稳定性和功能性的取舍，选了稳定性。要看更细的区间就换时间范围。

**为什么剂量只能从阶梯里选？** 界面上没有任何剂量自由输入。替尔泊肽只给 2.5/5/7.5/10/12.5/15 mg 这几个说明书核准的档位。用户打不出说明书里不存在的剂量。

**为什么身高没有默认值？** 没填身高时 BMI 显示"填身高才能算"，而不是拿一个默认身高编一个数字出来。**编出来的 BMI 比不显示更危险。**

**为什么提醒用 AlarmManager 而不是 WorkManager？** 提醒是每天固定钟点，不需要 JobScheduler 的网络/充电约束，也少一个依赖。代价是重启后要自己重排（`BootReceiver`），以及闹钟只读本地缓存的时间表——不依赖后端进程活着。

## 隐私

- 所有数据存在本机 SQLite，没有任何遥测、上报或云同步
- 华为运动健康数据通过**解析本地导出文件**导入（HiTrack 轨迹格式），不涉及任何逆向或注入
- AI 教练是可选的，用你自己的 API key，请求直接发给你配置的端点
